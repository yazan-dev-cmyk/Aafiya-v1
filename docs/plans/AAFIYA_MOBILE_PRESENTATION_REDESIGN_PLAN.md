# وثيقة خطة إعادة التصميم الشاملة لتطبيقي AAFIYA Patient وAAFIYA Pro
## للمراجعة والاعتماد البشري فقط (Pre-Implementation Architectural Plan)

---

## 1. الهدف وحدود النطاق (Objective & Scope Boundaries)

### 1.1 الهدف الأساسي
تهدف هذه الخطة إلى استكمال وتوحيد التجربة البصرية والواجهات الداخلية لتطبيقي الهاتف الذكي (`AAFIYA Patient` و`AAFIYA Pro`) وفقًا للمرجعية التصميمية المعتمدة في النموذج التفاعلي `aafiya-home-prototype.html` ونظام التصميم المشترك `aafiya_ui`، مع ضمان الحفاظ الصارم على استقرار المنطق البرمجي، الصلاحيات الأمنية، وقواعد العمل المعتمدة.

### 1.2 القيود الحاكمة الصارمة (Strict Non-Negotiable Guardrails)
- **وضع القراءة فقط والتوثيق:** هذه الوثيقة مخصصة للمراجعة والاعتماد البشري فقط، ولا تشكل ترخيصًا بالبدء في التعديل البرمجي أو الاختبار أو البناء أو النشر.
- **صفر تعديل على الباك إند أو قواعد البيانات:** منع تام لأي تعديل على ملفات `backend/` أو تشغيل تهيئة بيانات (seeders) أو ترحيلات (migrations) أو استعلامات SQL خام أو مساس بقاعدة البيانات الحية `medical_db`.
- **حماية وثائق الحوكمة:** يمنع تعديل ملفات `MASTER_PLAN.md` أو `EXECUTION_TRACKER.md` أو `DECISION_REGISTER.md`.
- **حظر العمليات المسبقة:** لا يتم تشغيل الاختبارات أو أوامر بناء الـ APK أو النشر على Railway أو الرفع عبر Git إلا بعد صدور إذن خطي مستقل ومعتمد من المستخدم.

## 2. مرجع التصميم والقرارات المعتمدة (Design Reference & Invariants)

### 2.1 المرجع البصري الأساسي
- **الملف المرجعي:** `/home/yazan/Downloads/aafiya-home-prototype.html`
- **حزمة المكونات المشتركة:** `mobile/packages/aafiya_ui`
- **حزمة النواة والبيانات والتعريب:** `mobile/packages/aafiya_core`

### 2.2 لوحة الألوان والسمات البصرية (Design Tokens)
تلتزم الخطة الصارمة بالرموز اللونية المستخرجة من النموذج المعتمد:
- `AafiyaColors.navy` (`#023E73`): الكحلي العميق للترويسات والأساس السيادي.
- `AafiyaColors.healthBlue` (`#0077B6`): أزرق الهوية الصحية والروابط والبطاقات.
- `AafiyaColors.tealDeep` (`#0B8074`): التيل الغامق لأزرار الإجراءات الأساسية ونداءات العمل (CTAs).
- `AafiyaColors.tealInk` (`#0A6F64`): التيل الداكن للنصوص التفاعلية والأيقونات النشطة.
- `AafiyaColors.tealSoft` (`#E0F5F2`): التيل الهادئ لكبسولات التبويبات النشطة وخلفيات الشارات.
- `AafiyaColors.scaffoldBg` (`#F4F8FB`): لون أرضية التطبيق لضمان تباين مريح مع البطاقات البيضاء (`#FFFFFF`).
- `AafiyaColors.surface` / `card` (`#FFFFFF`): خلفية البطاقات والحاويات الرئيسية.
- `AafiyaColors.border` (`#DCE6EE`): لون الحدود والفواصل الخفيفة للبطاقات والتبويبات.
- **الحالات الدلالية:** الأخضر النجاح (`#15803D` / خلفية `#E3F6EA`)، التحذيري (`#B45309` / خلفية `#FEF1DC` وشارة الجرس `#F59E0B`)، وحالات الطوارئ والخطأ (`#DC2626` / خلفية `#FDECEC` ونصوص طوارئ `#B91C1C`).

### 2.3 الخطوط والطباعة والاتجاهية (Typography & BiDi Safety)
- استخدام الخط العربي الرسمي `IBM Plex Sans Arabic` بأوزانه (400, 500, 600, 700).
- دعم كامل وصارم للغة العربية كاتجاه افتراضي من اليمين لليسار (RTL).
- حماية أرقام الهواتف، المعرّفات المرجعية، والتواريخ بعلامات العزل الاتجاهي Unicode BiDi Isolates (`\u200E...\u200E`) لمنع انعكاس الأرقام في الواجهات العربية.

### 2.4 مواصفات المكونات المرجعية الأساسية
1. **الترويسة المتدرجة ونمط الخاتم وشعار الهوية:**
   - `AafiyaHeroHeader`: تدرج لوني بزاوية 160° بالألوان `#023E73` (0%) إلى `#04569A` (60%) إلى `#0069A8` (100%)، بحشوة سفلية تسمح بتداخل البطاقة.
   - `AafiyaKhatamPattern`: نمط نجمة الخاتم الجزائري الثماني بشفافية 0.13 وتلاشٍ تدريجي نحو اليسار دون التأثير على وضوح النصوص.
   - `AafiyaBrandMark`: مساحة 40×40 بنصف قطر 13 وتدرج زمردي (`#27C3B1` إلى `#0B8074`) مع علامة زائد بيضاء واسم «عافية» في السياقات المناسبة.
   - جرس التنبيهات الزجاجي بشارة عداد برتقالية `#F59E0B`.
2. **تذكرة الموعد المتداخلة وحالة الفراغ:**
   - تداخل رأسي سالب مع الترويسة بهامش مستهدف يقع بين `-48.0` و `-62px` مع ظل هادئ.
   - `AafiyaTicketCard`: بطاقة بحواف جانبية مقصوصة دائريًا (radial notches) وفاصل منقط وأزرار إجراءات بتيل عميق `#0B8074` وزر فرعي محدد.
   - حالة الفراغ: كارت أبيض ناصع مع عنوان «لا توجد لديك مواعيد قادمة» وزر كامل العرض «ابحث عن مركز حجز» يوجه حصرًا إلى دليل مراكز الحجز.
3. **شبكة الاختصارات الأربعة (Shortcuts Grid):**
   - أربعة عناصر بأيقونات دائرية 58×58:
     - ابحث عن طبيب / مركز حجز: خلفية `#E6F1F9` وأيقونة `#0077B6`.
     - الوصفات الطبية: خلفية `#E0F5F2` وأيقونة `#0A6F64`.
     - السجل الطبي: خلفية `#E8EEFB` وأيقونة `#2B4FA8`.
     - الملف الإسعافي SOS: خلفية `#FDECEC` وأيقونة `#DC2626` ونص `#B91C1C`.
4. **دليل الأطباء والعيادات ومراكز الحجز:**
   - تبويبات كبسولية ثلاثية: «أطباء»، «عيادات»، «مراكز».
   - بطاقات أفقية `AafiyaDirectoryCard` بعرض 176dp تتضمن الاسم والتخصص والولاية ومؤشر «مفتوح الآن» فقط عند توفر مصدر موثوق له (EXCL-02).
5. **شريط التنقل السفلي (Bottom Navigation Bar):**
   - أربع وجهات: الرئيسية، مواعيدي، سجلاتي، حسابي.
   - كبسولة تيل ناعمة `#E0F5F2` للعنصر النشط وأيقونة ونص باللون `#0A6F64`.

### 2.5 القرارات المعمارية وسياسات العمل المعتمدة
- **قرار DISC-01 (Strict Discovery Isolation):** جميع شاشات وأدلة الاستكشاف (أطباء، عيادات، مراكز حجز) في تطبيق المريض هي واجهات استعلامية فقط، وتخلو تمامًا من إمكانية حجز المواعيد أو إنشاء الأطباء أو طلب الخدمات مباشرة. الحجز يتم حصرًا عبر مراكز الحجز المعتمدة أو الأطباء المرخصين.
- **سياسة QR وتصريح الزيارة:** عرض QR فقط عند توفر رمز تصريح زيارة آمن، مع إمكانية التكبير للمسح، ومنع تضمين أي بيانات طبية أو حساسة في نص الرمز.

## 4. الإنجاز السابق الذي لا يحتاج إلى إعادة تنفيذ (Completed Work Baseline)

لتجنب الهدر البرمجي وتكرار ما تم إنجازه بنجاح، يُثبت خط الأساس التالي باعتباره مكتملًا ولا يُعاد تنفيذه:

1. **شاشة `BookingCenterDirectoryScreen` في تطبيق المريض:** تم إنشاؤها وربطها بنموذج الباك إند مع شريط بحث وفلاتر الولايات وملاحظة DISC-01 وتنسيق BiDi للأرقام.
2. **فصل توجيه زر «ابحث عن مركز حجز»:** تم توجيهه في كارت الحالة الفارغة بـ `patient_home_shell.dart` إلى `BookingCenterDirectoryScreen.show(...)`.
3. **فصل تبويب «مراكز» وزر «عرض الكل»:** تم توجيههما في `patient_home_shell.dart` إلى `BookingCenterDirectoryScreen` مع الحفاظ على مسار `ClinicDirectoryScreen` لتبويب «عيادات».
4. **تحديث مكونات نظام التصميم الأساسية:**
   - تم تزويد `AafiyaAppBar` بخاصية `showBrandMark` المدمجة.
   - تم تزويد `AafiyaBrandMark` بمرونة القياس والحماية من الـ Overflow.
   - تم إضافة النصوص والترجمات الثلاثية (عربي، فرنسي، إنجليزي) لـ `disc01Notice` و`bookingCenterDirectoryTitle`.
5. **توزيع الشعار الأولي:** تم إدراج الشعار في شاشات تسجيل الدخول، ترويسات الأدلة، وتفاصيل المواعيد في كلا التطبيقين.

### 7.2 التعديل المنفذ في الكود الحالي
- تم إنشاء شاشة `BookingCenterDirectoryScreen` مستقلة تمامًا.
- تم ضبط التوجيه في `mobile/apps/aafiya_patient/lib/shells/patient_home_shell.dart`:
  ```dart
  // في بطاقة الحالة الفارغة:
  onButtonPressed: () {
    setState(() => _selectedDirectoryTab = 'centers');
    BookingCenterDirectoryScreen.show(context, apiClient: widget.apiClient);
  }
  // في زر عرض الكل والكاروسيل الأفقي:
  if (_selectedDirectoryTab == 'centers') {
    BookingCenterDirectoryScreen.show(context, apiClient: widget.apiClient);
  } else if (_selectedDirectoryTab == 'clinics') {
    ClinicDirectoryScreen.show(context, apiClient: widget.apiClient);
  } else {
    DoctorDirectoryScreen.show(context, apiClient: widget.apiClient);
  }
  ```

## 9. المخاطر والاعتماديات والنقاط التي تحتاج إلى قرار بشري (Risks & Decisions)

### 9.1 المخاطر التقنية
1. **مخاطر تجاوز المساحة (Layout Overflow):** عند تكبير الخط أو النصوص المترجمة للفرنسية، يجب إلزام كافة النصوص داخل الصفوف بـ `Flexible` و`TextOverflow.ellipsis`.
2. **مخاطر كسر واجهات الاختبارات:** أي تغيير في المعرفات النصية أو التسميات يتطلب تدقيقًا مباشرًا لتفادي كسر الـ Finders في الاختبارات القائمة.
3. **مخاطر التعديل العرضي لمنطق الأعمال:** حماية دوال الحجز والإلغاء وتعديل الجداول في Pro من أي لمس برمجِي أثناء إعادة التنسيق البصري.

### 9.2 القرارات المطلوب اعتمادها من المستخدم
1. **اعتماد نمط التذكرة المحفورة في تفاصيل الموعد:** هل تعتمد تطبيق الحواف الدائرية المقتطعة (`AafiyaTicketCard`) على صفحة تفاصيل الموعد كاملة كإيصال طبي معتمد؟

3. **قرار الرفع والنشر النهائي:** اعتماد خطة الإصدار المكونة من خطوة بناء APK تليها موافقة صريحة قبل أي رفع إلى GitHub أو نشر على Railway.
